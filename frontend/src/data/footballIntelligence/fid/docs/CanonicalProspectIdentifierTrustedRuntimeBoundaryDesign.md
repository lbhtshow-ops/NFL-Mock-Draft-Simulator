# Canonical Prospect Identifier Trusted Runtime Boundary Design

`CANONICAL_PROSPECT_IDENTIFIER_TRUSTED_RUNTIME_BOUNDARY_DESIGN` version `1.0.0` is the implementation design for a future non-production Supabase Edge Function named `canonical-prospect-identifier-issuance`. It binds the Sprint 13 host decision to the Supabase Edge Deno runtime while remaining `DESIGNED_NOT_IMPLEMENTED`.

The endpoint is a domain operation spanning the four approved prospect identity layers. It accepts only a small transport envelope referencing the existing issuance request, Sprint 5 authorization, actor, idempotency scope, timeout policy, and audit metadata. Bearer material exists only at the future HTTP authentication boundary: token contents never enter domain contracts, fixtures, snapshots, or logs. Authentication establishes a minimal actor reference; it never grants issuance authority. Sprint 5 remains the authorization owner.

The server-only composition design declares twelve dependencies: authentication verification, authorization evaluation, issuer planning, generator port, generator adapter, entropy provider, platform secure source, output encoder, issuer structural validator, idempotency capability, persistence transaction port, and audit metadata provider. All dependencies are declarations with null implementations and false execution permission. The 23-stage invocation plan preserves each existing owner rather than duplicating issuer behavior inside the runtime owner.

The secure-source boundary is the Deno Web Crypto platform-backed CSPRNG capability category. A future adapter must return exactly 16 bytes or a governed failure; partial output, deterministic development fallback, source retry, encoding, candidate assembly, persistence, and policy ownership are prohibited. The encoder remains bound to `CANONICAL_PROSPECT_IDENTIFIER_ENCODING_POLICY@1.1.0`: RFC 4648 unpadded Base64URL, exact approved alphabet, 22 characters, no padding, case preserved. No example or candidate exists.

After issuer structural validation, a future narrow Postgres RPC/transaction must atomically coordinate authoritative collision detection, reservation, issuance-ledger writing, canonical identifier binding, and idempotency result recording. It cannot own entropy, encoding, strategy, authorization, tokens, or application orchestration. Matching replay returns the stored governed result without generation; mismatched replay fails. An uncertain commit or post-commit disconnect requires ledger reconciliation and never blind retry. Cancellation after commit cannot undo issuance.

CORS is restricted by configuration reference and is distinct from authentication. Service credentials, JWT verification configuration, origins, RPC identity, timeouts, and rate limits are server-only references without values. Audit logs allow references and categorical outcomes only; tokens, authorization payloads, entropy, encoded material, candidates, secrets, full requests, personal facts, raw platform/Postgres errors, and sensitive stack traces are prohibited. Entropy is future-ephemeral, uncached, never module state, and released promptly without claiming JavaScript zeroization guarantees.

Shared declarations remain under `src/data/footballIntelligence/fid/prospectIntake`. Future implementation belongs under `supabase/functions/canonical-prospect-identifier-issuance`; that directory was not created. Browser imports of runtime implementation are prohibited. Initial integration tests stop before live authentication, entropy, RPC, or persistence. Deployment proceeds through contract tests, dormant local and preview surfaces, security review, and explicit non-production activation review. Rollback disables invocation first and preserves ledger/idempotency history without provider switching or policy downgrade.

The assessment is `TRUSTED_RUNTIME_BOUNDARY_READY_FOR_NON_PRODUCTION_IMPLEMENTATION`. Exact values for CORS origins, timeout, body limit, rate limits, JWT actor mapping, RPC signature, and region remain implementation-review inputs. Final readiness is `READY_FOR_CANONICAL_PROSPECT_IDENTIFIER_TRUSTED_RUNTIME_NON_PRODUCTION_IMPLEMENTATION`; the next sprint is **Canonical Prospect Identifier Trusted Runtime Non-Production Implementation**.
